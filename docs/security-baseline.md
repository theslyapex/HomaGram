# خط مبنای امنیت

این سند چک‌لیست اولیه است و به معنی تکمیل یا ممیزی امنیتی محصول نیست.

- هیچ Secret یا service_role key در اپ موبایل یا مخزن قرار نمی‌گیرد.
- کنترل مجوزها باید سمت سرور و در دیتابیس enforce شود.
- برای تمام جداول در معرض Data API، RLS و policyهای محدود به مالکیت/نقش واقعی لازم است.
- داده‌های نقش مدیریتی نباید از metadata قابل‌ویرایش کاربر برای تصمیم‌گیری مجوز استخراج شوند.
- ورودی‌ها و فایل‌های بارگذاری‌شده باید اعتبارسنجی شوند.
- محدودسازی نرخ درخواست، جلوگیری از درخواست تکراری و ثبت رویدادهای امنیتی در مراحل مربوط پیاده‌سازی می‌شوند.
- گزارش و مسدودسازی کاربران باید پیش از آزمون عمومی در دسترس باشد.
- تا زمان طراحی و بررسی تخصصی رمزنگاری سرتاسری، محصول نباید ادعای E2EE داشته باشد.
- دسترسی‌های مدیریتی باید نقش‌محور، محدود و قابل ممیزی باشند.

هر قابلیت امنیتی پس از پیاده‌سازی باید با تست و بازبینی policyها تأیید شود.
